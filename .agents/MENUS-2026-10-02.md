## 1. Resumen ejecutivo

- **PuntoByZE ya tiene exactamente dos menús**, con datos, orden y dibujo distintos:
  el **menú de catálogo de 3 niveles** (editorial: 14 categorías / 84 grupos / 367
  destinos) y el **menú compacto de 2 niveles** (árbol real del mayorista: 36
  categorías / 363 subcategorías, ordenado por `orden`).
- El **tercer nivel** de PuntoByZE no son solo subcategorías: son **destinos**
  (subcategoría, marca o filtro). El segundo nivel son **grupos comerciales** que
  reagrupan las categorías reales; una misma categoría real aparece en varios
  grupos (por eso hace falta el tercer nivel).
- Valduran hoy tiene un megamenú de **2 niveles** y **ningún ajuste de menú** por
  tienda. Existe `mt_stores.header_style` (estilo de *cabecera*, con 3 valores:
  `classic`, `compact`, `centered`), que **no es** un tipo de menú y cuyo valor
  `compact` colisiona de nombre con el «Menú Compacto»: el ajuste nuevo debe ser
  un campo aparte con **exactamente dos** valores.
- **Decisiones cerradas en esta fase:**
  1. La documentación vive en el repositorio, en este fichero.
  2. El árbol de 3 niveles de Valduran nace como **semilla del árbol de PuntoByZE**
     (solo nombres y orden) y queda **editable en el panel**.
  3. Las URLs de navegación pasarán a ser **solo las rutas SEO estilo PuntoByZE**,
     con **301 desde todas las URLs actuales** (query string incluida).
- El nuevo menú debe aplicarse sobre la **tienda real de Valduran**. Hoy
  `valduran.com` sirve la **tienda demo** («Mi Tienda S.L.», «Calle Mayor 1,
  50001 Zaragoza»), sin logotipo: es un pendiente que hay que cerrar antes de
  publicar (ver §11).

### 2.4 Navegación y URLs de PuntoByZE

Esquema por segmentos, todo en la ruta (no en *query string*):

```
/{categoria}/{subcategoria}[/m/{id_marca}][/f/{id_filtro}-{id_subfiltro}]
    [/etiqueta/{todos|recomendados|top-ventas|oferta|novedades}]
    [/orden/{0|1|2}][/page/{n}]
```

- **Marca** por `m/`, **filtro** por `f/` (filtro-subfiltro), **etiqueta** y
  **orden** como segmentos; paginación con `/page/N`.
- Búsqueda rápida en `/q/{consulta}` (`__` sustituye al espacio, `--` a la barra).
- **301** para subcategorías fusionadas o eliminadas y coincidencia tolerante con
  *slugs* heredados.

### 2.5 Orden de productos y etiquetas de listado

- **Orden**: `Relevancia` (por defecto: productos propios primero + *scoring* por
  tokens del nombre) · `Precios Asc` · `Precios Desc`.
- **Etiquetas** (filtros comerciales de un clic): `Todos` · `Premium` (stock en
  almacén propio) · `Top Venta` (más vendidos en 30 días) · `Ofertas` ·
  `Novedades` (alta en los últimos 30 días).

## 5. Especificación de los dos menús

**Regla dura:** el ajuste de menú tiene **exactamente dos** valores
(`compacto` | `catalogo`). **No existe ni se creará una tercera variante.**
`header_style` (cabecera) es un ajuste distinto y no se multiplica.

Contrato de datos común (mismo array para los dos menús):

```
menú        -> [ { id, label, slug, total, children: [ ... ] } ]
nivel 1     -> categoría comercial                 (obligatorio)
nivel 2     -> grupo   (catálogo) / subcategoría (compacto)
nivel 3     -> destino: { type: subcategoria|marca|filtro|url, id, slug, label, badge? }
```

## 12.3 Decisiones que se confirmaron al implementar

1. **Una sola vista para los dos menús.** El requisito «exactamente la misma
   información» se garantiza por construcción: no hay dos plantillas que puedan
   divergir. El CSS/JS solo cambia la presentación (`data-menu-style`).
2. **El bloque promocional por AJAX.** `brandOptions` tarda 64–278 ms por categoría;
   pintarlo para las 14 categorías castigaría la primera visita. `GET /menu/panel/{id}`
   devuelve HTML ya renderizado (reutiliza `_card.php`), así el JS no duplica ni
   tarjetas ni colores y el menú funciona sin JavaScript.
3. **`f/…` se rechaza, no se aproxima.** Antes que enseñar un listado equivocado, 404.
   Las facetas que sí existen siguen en la query (`f[socket][]=am5`, `pmin`, `pmax`) y
   se conservan al entrar por una ruta SEO.
4. **Los destinos no resueltos nacen inactivos.** Si se sembraran activos, el menú
   enlazaría a páginas que no existen y el aviso quedaría escondido.
5. **Versión en la clave de caché.** El árbol cacheado cambia de forma al evolucionar;
   `menu_tree_v2_<id>` evita que un despliegue reutilice el JSON viejo (nos pasó: el
   bloque promocional pedía el id del nodo en vez del id de la categoría).
